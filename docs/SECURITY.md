# Security Model

> **Many security controls in this document are still not implemented.** As of 2026-08-31 the backend contract layer (config, errors, models, logging), the **URL/egress security boundary** (`app/security/url_validation.py`, `app/security/net_guard.py`), the **GitHub client that calls it** (`app/fetch/github.py`), the **streaming archive reader** (`app/fetch/archive.py`), the **import extractor** (`app/analysis/parser.py`), and the **ingestion+parse pipeline that joins them** (`app/analysis/pipeline.py`) exist. The pipeline sends the download, streams it into the reader, applies `is_secret_path` before any file is parsed, and enforces `MAX_SOURCE_FILES` — so several rows below have moved off `Planned`/`Partial` for the first time. `app/security/path_safety.py` still **has no caller**; a rule nothing applies protects nothing, which is why its row says so explicitly.
>
> **2026-09-01 — there is a routing layer, so the second of the three limits below no longer holds.** `app/api/` exists (ADR-023) and every control on the request path is now exercised *by an HTTP request* rather than by a direct call. Five rows moved as a result: "Unbounded graph" and "Oversized request body" from `Planned` to `Implemented` — both were constants nothing read — "Event loop starvation" likewise, and both "Information disclosure via errors" rows, since the contract in `app/errors.py` finally has something that returns it. Two rows were updated without moving: "Slow-loris" (the worker thread exists; the `asyncio.wait_for` deliberately does not) and "Source code in logs" (the response path was its open half). The **first** limit is unchanged and now matters more, not less: an HTTP request built by a test is still not a hostile repository.
>
> Three limits on what that means. First, **every control below is still exercised only against in-process fixtures** — respx swaps the transport and the tarballs are built by `tests/fixtures/tarballs.py`, and the network is blocked suite-wide. The ingestion path *has* been run against real GitHub repositories on 2026-08-31 (`backend/scripts/smoke.py`, ADR-014), which retires the "nothing has ever been fetched from GitHub" caveat — but that run exercised the **happy path only**. Real repositories are not hostile, so not one control below was actually *triggered* by real data: a guard that wrongly rejected a legitimate repository would now be caught, a guard that fails to stop an attack would not. Second, ~~there is still no routing, so no control below is exercised by an HTTP request~~ — **retracted 2026-09-01**, see the note above; `tests/test_api_routes.py` drives the real application. Third, `/api/source` does not exist, so any row requiring *two independent* call sites stays `Partial` no matter how good the one that exists is. Rows marked `Implemented` name the file; treat every other row as aspirational. Flip a row only when you have seen the code, and name the file in the same edit.
>
> Note in particular that the limit *constants* have existed in `app/config.py` since before anything read them. **A constant is not a control.** Every remaining row describing enforcement of a node/edge, file-count, rate, or duration limit stays `Planned` until code reads that constant and rejects something.

## Trust Model

The analyzed repository is **hostile input**, in full: its URL, its archive structure, its file paths, its file contents, and its configuration files. Nothing derived from it is trusted, and none of it is ever executed.

The operator's environment (server filesystem, network position, `GITHUB_TOKEN`) is the thing being protected from it.

## Assets

| Asset | Why it matters |
|---|---|
| `GITHUB_TOKEN` | Optional, for API rate limits. Leaking it exposes the operator's GitHub account. |
| Server filesystem | Traversal or symlink escape could read or overwrite host files. |
| Internal network | The server can reach hosts a remote user cannot — the classic SSRF prize (cloud metadata endpoints, internal services). |
| Server CPU / memory / bandwidth | Finite and shared; exhaustion is a denial of service against all users. |
| Analyzed source code | A user's repository content. Must not be logged, retained, or leaked to other users. |
| Secrets inside analyzed repos | Repositories commonly contain committed `.env` files and keys. We must not surface them. |
| The browser session | XSS via repository content would run in the origin of the app. |

## Threats and Controls

Every control below is **`Planned`** unless its Status cell says otherwise.

### Network / SSRF

| Threat | Risk | Mitigation | Status |
|---|---|---|---|
| Arbitrary URL fetched from user input | Critical | Accept only `https://github.com/<owner>/<repo>`, parsed against a strict grammar; the download host is never user-supplied | **Implemented** — the grammar is `app/security/url_validation.py`; `app/fetch/github.py` builds every request URL from `https://api.github.com` plus path segments re-validated against a fixed character set, so no user string chooses a host |
| Redirect to an attacker host | Critical | `follow_redirects=False` everywhere; exactly one redirect permitted, its host compared by **string equality** against a one-element allowlist (`codeload.github.com`) — never `endswith`, which `codeload.github.com.evil.com` defeats | **Implemented** — the equality allowlist is `app/security/net_guard.validate_download_url`; `follow_redirects=False` and the single validated hop are `app/fetch/github.py`. A `Location` on a non-redirect status is not followed, and each refusal test asserts the disallowed hop is never requested |
| DNS rebinding / hostile resolver | High | Resolve the host and require every returned address to be globally routable — `is_global`, **plus** `not is_reserved`, `not is_multicast`, and `not is_site_local`, after unmapping `::ffff:`. All three extras are load-bearing: on CPython 3.14.7 `is_global` is `True` for `::127.0.0.1`, `64:ff9b::7f00:1`, `224.0.0.1`, and every address in `fec0::/10`. A sweep of all 65 536 IPv6 `/16` prefixes confirms those four predicates leave no further gap | **Implemented** — `app/security/net_guard.assert_public_ip`; no caller yet |
| Private / loopback / link-local targets | Critical | Rejected by both the URL grammar and the resolved-IP check. Explicitly: `localhost`, `127.0.0.1`, `::1`, `10/8`, `172.16/12`, `192.168/16`, `169.254.169.254` | **Implemented** — `app/security/url_validation.py` and `app/security/net_guard.py` |
| Non-HTTPS or non-HTTP schemes | High | Scheme must be exactly `https`; kills `file:`, `ftp:`, `javascript:`, and protocol-relative `//evil` Locations | **Implemented** — `app/security/url_validation.py` and `app/security/net_guard.py` |
| Proxy env vars redirecting traffic | Medium | `trust_env=False` on the HTTP client, ignoring `HTTP_PROXY` / `ALL_PROXY` / `NO_PROXY` | **Implemented** — `app/fetch/github.create_client` |
| Credential leak to a redirect target | High | The tarball download request is issued **without** an `Authorization` header. If host validation were ever bypassed, no token leaves the process | **Implemented** — `app/fetch/github.py`. The client holds no `Authorization` default at all; the token is a per-request header on `api.github.com` only, and `download_request()` pops any inherited one (ADR-009) |
| Homograph / lookalike hostnames | Medium | ASCII-only check on the raw URL before parsing | **Implemented** — `app/security/url_validation.py` |
| URL parser differential | Medium | `urlsplit` silently deletes tab/CR/LF anywhere in a URL, so `https://gith<TAB>ub.com/o/r` parses as `github.com`. Both modules screen C0 controls, space, DEL, and `\` **before** parsing, so no accepted URL can read differently to a human than to the parser | **Implemented** — `app/security/url_validation.py` and `app/security/net_guard.py` |

> **Residual risk — DNS rebinding is narrowed, not closed.** `assert_public_ip` resolves the name, but the connection that follows is made *by name*, so a resolver that answers differently the second time is not caught. Closing it fully requires connect-by-IP with SNI, which v1 does not do.

### Command injection

| Threat | Risk | Mitigation | Status |
|---|---|---|---|
| Shell metacharacters in a repo URL or path | Critical | **No `subprocess` in the ingestion or analysis path at all.** No `git`, no shell, never `shell=True`. Downloading is an HTTP request; extraction is `tarfile` | **Implemented** — the ingestion *and* analysis paths now both exist (`app/fetch/github.py`, `app/fetch/archive.py`, `app/analysis/pipeline.py`, `app/analysis/parser.py`) and no module under `app/` imports `subprocess` or calls `os.system`, `exec`, or `eval`. Owner, repo, and ref are percent-encoded per path segment after a character-set check. **The routing layer now exists and did not reintroduce one** — `app/api/` imports no `subprocess`, spawns no process, and touches no path: the only thing it does with the user's string is hand it to `parse_github_url` |
| Git-mediated code execution | High | `git clone` is deliberately not used — git honors `.gitattributes` filters and `core.*` config, which are attacker-controlled | **Implemented** — ingestion is an HTTPS fetch plus `tarfile`; no git invocation exists anywhere in the repository. Archive members are read as bytes and never interpreted, so `.gitattributes` is just another file |

### Path traversal and archive attacks

| Threat | Risk | Mitigation | Status |
|---|---|---|---|
| `../../etc/passwd` in an archive member | High | **No file is ever written to disk** (ADR-003), so traversal has no write target. Member paths are still rejected if any component is `""`, `.`, or `..`, after normalizing `\` to a separator | **Implemented** — `app/fetch/archive._check_member_name`. The `\` normalization is load-bearing below the root directory, where the root-name pattern cannot help: `root-sha/src\..\..\evil.ts` is otherwise one component that is not `..` |
| Absolute paths in members | High | Reject `/…`, `C:\…`, `\\…` | **Implemented** — `app/fetch/archive._check_member_name`. Redundant by design (a leading separator becomes an empty component; a drive letter becomes a root that fails `ROOT_PATTERN`), and annotated as such in the code |
| Symlink / hardlink escape | High | Only regular files are read. `issym`, `islnk`, `ischr`, `isblk`, `isfifo` are skipped and counted, never followed | **Implemented** — `app/fetch/archive.iter_source_files`. `extractfile` is called only after `isfile()`, so a link target is never resolved and `linkname` is never read |
| Traversal via the `/api/source` path parameter | High | Path must match an HMAC token issued by the analyzer for that exact `owner/repo@sha:path`; forged paths cannot produce a valid token, and a token minted for one path cannot be replayed against a different `owner/repo@sha:path` (ADR-007) | Planned — **and out of MVP scope.** ADR-013 removed `/api/explain`, which was this mechanism's only in-scope caller, so `/api/source` and the token are deferred as one unit. No MVP endpoint takes a path parameter at all, which is why this threat has no reachable surface today |
| Zip/tar bomb | High | Cumulative decompressed cap (256 MiB) **plus** a compression-ratio guard (max 100:1, enforced once past an 8 MiB floor) so a gigabyte-of-zeros bomb trips at ~8 MiB | **Implemented** — `app/fetch/archive._DecompressedStream`. Both are metered on the *decompressed stream*, on every read, not per accepted member: a non-seeking `tarfile` reads past the body of a member this module skips for being oversized, so a 1 GiB bomb yields no files at all and would be invisible to a per-member accounting |
| Malicious member names (NUL, lone surrogates) | Medium | Reject names containing NUL or failing a strict UTF-8 round-trip — `tarfile`'s `surrogateescape` decoding otherwise leaks raw bytes | **Implemented** — `app/fetch/archive._check_member_name`. A NUL is reachable only through a pax `path` header; the ustar name field is NUL-terminated, so `tarfile` truncates there |
| Archive with multiple root directories | Medium | Root must match `^[A-Za-z0-9._-]+-[0-9a-f]{7,40}$` and be identical across all members | **Implemented** — `app/fetch/archive.ROOT_PATTERN` and the root-equality check in `iter_source_files`. Applied to regular files; directory and link members are skipped before it, which is safe only because nothing is written |
| Unicode-normalization traversal | Medium | Member names are compared as the exact code points the archive carried — **nothing normalizes them**. NFKC would fold U+FF0E to `.` and U+FF0F to `/`, turning an inert component into `../etc/passwd` | **Implemented** — by construction, in `app/fetch/archive._check_member_name`, and pinned by test. The residual risk is *downstream*: anything that later normalizes a yielded path — a normalizing filesystem, a `unicodedata.normalize` before a comparison, a database collation — undoes the guarantee. A yielded path is a node ID and an `/api/source` subject, so it must be compared byte-for-byte |
| Future disk I/O reintroducing traversal | Medium | `security/path_safety.safe_relative_path()` — realpath the base *and* the candidate, then require `commonpath` to equal the base. Implemented and tested even though nothing currently writes files, so the first caller to need disk I/O finds a correct primitive rather than an `os.path.join` | **Implemented** — `app/security/path_safety.py`; no caller, by design. `commonpath` rather than `str.startswith`, which accepts the sibling `/srv/base-evil` as a child of `/srv/base`; the base is resolved too, or a symlinked base would refuse every call |

### Malicious repository code

| Threat | Risk | Mitigation | Status |
|---|---|---|---|
| Repository code executed | Critical | Parsing only. No dependency install, no build scripts, no package scripts, no interpreters, no Makefiles, no shell scripts | **Implemented** — `app/analysis/pipeline.py` is the whole of what happens to a repository: archive members are read as bytes, judged by path, and handed to tree-sitter. `package.json` is not read at all yet, and a `Makefile` or a `.sh` is just an unsupported extension. Nothing under `app/` imports `subprocess` or calls `exec`/`eval` |
| Parser crash or hang on crafted input | Medium | Per-file size cap (1 MiB), binary detection, a pathological-parse-tree guard, and a whole-file `except Exception` plus explicit `RecursionError`/`MemoryError`. A failed file is skipped and reported, never fatal | **Implemented** — `app/analysis/parser.py`. **Not by the mechanism this row used to name:** `progress_callback` is unusable in tree-sitter 0.26.0, so the bound is structural. See the note below |
| Parser hang via the *query*, not the parse | High | Refuse any tree containing an ERROR node wider than `MAX_ERROR_NODE_CHILDREN` (1000), with `MAX_PARSE_TREE_VISITS` (100 000) as a backstop for a file of pervasively small errors | **Implemented** — `app/analysis/parser._is_pathological`. tree-sitter's query engine is quadratic in the *width* of an ERROR node: a 1 MiB file of `(` parses in 0.23 s and then takes **~11 minutes** to query — measured 0.09 / 0.95 / 3.97 s at 10k / 40k / 80k children, fourfold per doubling. Every pattern in the query costs the same, so it is the traversal and not the pattern; nesting *depth* is not the trigger (20 000 levels query in 4 ms). Guarded, the worst case across a sweep of hostile 1 MiB inputs is ~3.3 s, and that remainder is parse time |
| Phantom dependencies from commented-out or stringified imports | Medium (correctness) | tree-sitter AST queries rather than regex, so `// import 'x'`, `/* import */`, `"import 'x'"`, `` `import('${x}')` ``, `require(v)`, and `import.meta` are correctly ignored | **Implemented** — `app/analysis/parser.IMPORT_QUERY`, with ten negative cases in `tests/test_parser.py`. The `require` filter runs in Python over `QueryCursor.matches()`, **not** `captures()`: `captures()` returns callees and strings as two independently ordered lists with the match association discarded, so it cannot tell `require('./real')` from `describe('not an import')`. Using it would either drop every `require` or invent an edge per test name |

> **The `progress_callback` route is closed, and that is worth stating plainly because the obvious fix looks available and is not.** In tree-sitter 0.26.0 — the current release; there is no newer one — `Parser.parse(source, progress_callback=…)` is *ignored* for a `bytes` source (it emits `UserWarning: The progress_callback is ignored when parsing a bytestring` and never calls back, and `filterwarnings = ["error"]` turns that warning into a test failure), and **segfaults the interpreter** for the chunked-reader source form as soon as the callback actually fires, with the C stack in `PyObject_IsTrue` inside `_binding`. A segfault takes the worker with it and no `except` can catch it, which is strictly worse than the hang it was meant to prevent. `Parser.timeout_micros`, the older mechanism, was removed. There is therefore **no in-parse timeout available at all**: the `Deadline` cannot preempt a parse already under way, and is checked before the parse and again between the parse and the query. Per-file cost is bounded by `MAX_PARSE_BYTES` and `_is_pathological` instead. Re-test before reaching for `progress_callback` again — see ADR-010.

### Resource exhaustion / DoS

| Threat | Risk | Mitigation | Status |
|---|---|---|---|
| Huge repository | High | GitHub-reported size preflight (256 MiB) before download; compressed cap 64 MiB; extracted cap 256 MiB | **Implemented** — the preflight is `app/fetch/github.get_repo_metadata`; the compressed cap is `app/fetch/archive._CountingRawStream` (enforced eagerly as bytes arrive, so it bounds bandwidth and the adapter's own buffer) and the extracted cap is `_DecompressedStream` |
| Huge individual file | Medium | 2 MiB member cap, 1 MiB parse cap | **Implemented** — the 2 MiB member cap is `app/fetch/archive.iter_source_files`; the 1 MiB parse cap is `app/analysis/parser._parse`. An oversized file is skipped at both layers, never fatal |
| Thousands of files / deep nesting | Medium | 50 000 archive members, 3 000 parsed source files, depth 32, path length 1024 | **Implemented** — the member cap, depth cap, and path-length cap are `app/fetch/archive.iter_source_files`; depth and length are measured on the path *after* the archive root is stripped, so they do not vary with the repository's name. `MAX_SOURCE_FILES` is `app/analysis/pipeline._analyze`, counted over **accepted** files rather than archive members, so a repository of assets is not truncated by its assets. Truncation sets `truncated` and is taken from the front of archive order, so it is deterministic and flagged, never silent; reaching the cap abandons the generator and therefore the download, which is why no count of what was left behind is reported — that number cannot be produced without paying for the rest of the transfer |
| Unbounded graph | Medium | 6 000 node / 20 000 edge caps; truncation is deterministic and flagged in stats, never silent | **Implemented** — `app/analysis/graph_builder.build_graph`, applied by `app/api/routes._analyze_blocking` via `GraphLimits.from_settings`. ADR-018 offered the router two ways to cap and ADR-023 took the second: the builder builds a **smaller graph** rather than the router slicing a larger one, because `stats.dependencies == len(edges)`, the per-node `imports`/`importedBy`, `stats.files`, `stats.directories`, both import totals and every directory aggregate are computed inside it and an after-the-fact slice falsifies all eight — and can leave an edge naming a node that is gone. Nodes are cut to a **prefix of component order**, which is closed under `parent` (a path's parent is a prefix of it, so a parent always sorts first), edges naming a dropped node are removed, the edge cap applies to what remains, and only then are the counters derived. Deterministic and flagged: `stats.truncated`, the same flag the pipeline's two caps set. 11 tests in `tests/test_graph_builder.py` and 4 over a whole response in `tests/test_api_routes.py`; ten mutations of the cap logic were tested one at a time and all ten are caught |
| **Post-parse analysis runs outside the deadline** | **High** | `MAX_IMPORTS` caps the total import count in the pipeline, bounding the phase that has no clock (ADR-019) | **Implemented for the import half** — `app/analysis/pipeline._analyze` counts every import as it leaves `extract_imports` and stops parsing at `MAX_IMPORTS` (100 000), setting `truncated` and `imports_truncated`. The count is a running total across files and is checked per import, so a single 1 MiB file cannot overshoot it. `resolve_imports` and `build_graph` still take **no `Deadline`** — deliberately: a clock there makes output non-deterministic and a partial resolution indistinguishable from a genuinely unresolvable import, and a cap downstream would falsify `stats.dependencies == len(edges)` (ADR-018, ADR-019). The bound is the count, upstream. Measured 2026-08-31 on the same 3000 x 334 fixture: **1 002 000 imports / 76.1 s resolve / 81.8 s total** before, **100 000 imports / 7.7 s resolve / 8.2 s total** after. Worst case is now ~60 s parse + ~8 s resolve — bounded and known, not free. **The graph-size half of this row closed on 2026-09-01** (ADR-023): `MAX_NODES`/`MAX_EDGES` are enforced by the builder itself when the router asks for a capped graph (row above). The builder measured linear and cheap and was never the cost problem — that half of the row was about response size, not about time |
| Slow-loris or endless analysis | High | Cooperative `Deadline` (60s) checked between archive members and around each parse. `asyncio.wait_for` cannot kill a thread, so the deadline — not the timeout — is the real mechanism | **Partial** — `app/analysis/deadline.py` (monotonic, frozen so a step cannot extend its own budget), checked between archive members by `app/fetch/archive.iter_source_files`, twice per file by `app/analysis/parser._parse` — once before the parse, once after it — and again by `app/analysis/routes.detect_routes` before its own traversal. *(Corrected 2026-08-31: this named `parser._collect`, which ADR-021 split into `_parse` and `_imports`. The post-parse check moved into `_parse`, so it now guards every query run over the tree rather than only the import one.)* **It cannot preempt a parse or a query already running** (see the `progress_callback` note above), so per-file cost is bounded structurally rather than by the clock; the deadline stops the *next* unit of work, not the current one. The request-scoped construction now exists — `app/analysis/pipeline.analyze_repository` builds exactly one `Deadline` from `ANALYSIS_TIMEOUT_S` and threads it through the fetch, the reader, and every parse, letting `AnalysisTimeoutError` propagate. **A route now calls it, on a worker thread** (`app/api/routes.analyze`, via `asyncio.to_thread`). There is still **no `asyncio.wait_for` net, and that is now a decision rather than an omission** (ADR-023): it cannot kill a thread, so it would return a 504 while the work continued, and a client retrying on that 504 would add live threads rather than shed them. The bound is the cooperative one — `Deadline`, httpx's 5 s connect / 15 s read timeouts under it, and `MAX_IMPORTS` over the clockless phase after it. The slow-loris half is about a connection **the ASGI server** accepts, so it remains the server's timeout to set at deploy time. Concurrent analyses are now bounded by the row below (`ConcurrencyGate`, ADR-008) |
| Request flooding | High | Per-IP sliding window (5/min, 60/hour on analyze) plus a global concurrency semaphore (3) with a fast 503 | **Implemented** — `app/api/rate_limit.py` (`SlidingWindowLimiter`, `ConcurrencyGate`, ADR-008), checked by `app/api/routes.analyze`. The window is checked before `parse_github_url`, refusing with 429 and a `Retry-After` header (`RateLimitedError`, which is the one `AppError` subclass carrying per-instance data — a wait time, never body text); the gate is checked immediately before the worker thread would be spawned, refusing with 503 (`ServerBusyError`) rather than queuing. Not a semaphore: `asyncio.Semaphore` would queue a waiter until a slot frees, which is the opposite of shedding load fast. Both structures live on `app.state`, one pair per process |
| Cross-origin drive-by (a page at another origin driving the visitor's browser into `/api/analyze`) | Medium | Explicit origin allowlist with no wildcard and no reflected `Origin`; a browser blocks both the preflight and the response read for any origin not named | **Implemented** — `CORSMiddleware` as the **outermost** middleware in `app/api/app.py`, origins from `Settings.CORS_ALLOWED_ORIGINS` (default empty = nothing allowed cross-origin), methods GET/POST/OPTIONS only, headers `Content-Type` only, no credentials (ADR-028). CORS is browser-enforced, not auth: a disallowed origin still gets its request processed, but without an `Access-Control-Allow-Origin` header the browser refuses to read the response. Not a substitute for the rate limiter or the concurrency gate — a non-browser client ignores CORS entirely, which is why both rows above stay load-bearing. Four route-level tests in `tests/test_api_routes.py` |
| Oversized request body | Medium | 4 KiB cap enforced by ASGI middleware checking `content-length` **and** counting bytes on chunked bodies (Starlette does not cap bodies) | **Implemented** — `app/api/middleware.BodySizeLimitMiddleware`, pure ASGI rather than `BaseHTTPMiddleware`, which buffers the body into a stream before the endpoint sees it and would defeat the point. Both halves: a declared `Content-Length` over `MAX_REQUEST_BODY_BYTES` is refused **before a byte is read**, and a chunked body — which declares nothing — is refused by counting delivered bytes. The refusal is written by the middleware rather than raised, because `fastapi.routing.get_request_handler` wraps the body read in `except Exception: raise HTTPException(400, …)` and would turn a typed 413 into a "malformed JSON" 400 (verified against fastapi 0.141.1); the body is still built from `errors.PayloadTooLargeError`, so its shape has one source. An oversized body therefore never reaches application code. Both halves are separately mutation-tested, and the declared-length check has its own test asserting **not one chunk is pulled** — without it, deleting the check leaves everything green because the counter catches the same request one cap later |
| Event loop starvation by CPU-bound parsing | Medium | Analysis runs on a worker thread so health checks and the rate limiter stay responsive | **Implemented** — `app/api/routes.analyze` sends the whole blocking span to `asyncio.to_thread` in one piece: the download, every parse, `resolve_imports`, `build_graph`, and the response model. Resolution alone is measured at up to ~8 s with no clock (ADR-019), so leaving it on the loop would stall `/api/health` for the full budget |

### XSS and frontend

| Threat | Risk | Mitigation | Status |
|---|---|---|---|
| XSS via source code in the preview | High | Syntax highlighting via shiki's `codeToTokens` rendered as React `<span>` text children. **No HTML string is ever constructed**, making the viewer structurally incapable of injection | Planned |
| XSS via repository metadata (paths, names) | High | All repo-derived strings rendered as React text. `react/no-danger` set to `error` so the no-`innerHTML` rule is mechanically enforced, not aspirational | Planned |
| Malicious/oversized API response | Medium | zod validation at the boundary with hard caps; dangling edges dropped rather than throwing | **Implemented** — `frontend/src/api/client.ts` (**2026-09-01**) runs every response through `AnalyzeResponseSchema.safeParse` before anything else touches it, and `frontend/src/graph/elements.ts` drops a node with an unknown `parent` or an edge with an unknown endpoint rather than letting `cy.add()` throw and take the whole canvas down. Exercised against a live backend, not only reasoned about: three real repositories validated unmodified |
| Node IDs used unsafely | Medium | IDs are used only as Map keys and React keys — never as DOM ids, never interpolated into a URL | Planned |
| Script injection via CSP gaps | Medium | `script-src 'self'`, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`. Shiki uses its JavaScript regex engine, not WASM, so `wasm-unsafe-eval` is not needed | Planned |

> **Known accepted weakness:** the CSP will need `style-src 'unsafe-inline'` because shiki tokens carry inline `style={{color}}`. Documented upgrade path: a theme has a bounded color set, so a `hex → className` map injected via `sheet.insertRule()` (CSSOM is not CSP-restricted) removes the need. Not planned for v1; inline *style* is orders of magnitude lower risk than inline *script*.

### Secret exposure

| Threat | Risk | Mitigation | Status |
|---|---|---|---|
| Returning `.env`, keys, credentials | High | Deterministic secret-path filter applied during analysis **and** re-applied independently in `/api/source` from the same shared module, so a forged token still cannot extract them | **Partial** — the rule is `app/security/secret_filter.is_secret_path`, and it now has its **first** caller: `app/analysis/pipeline._analyze` applies it to every path the archive yields, before the bytes reach the parser, so a committed `.env` is never parsed, never becomes a node, and never gets a description. A test spies on `extract_imports` to pin the ordering rather than only the outcome. **The end-to-end half is now asserted over a real response** (2026-09-01): `tests/test_api_routes.test_the_secret_file_reaches_no_part_of_the_response` analyzes a repository containing a `.env` over HTTP and asserts neither its path nor its contents appear anywhere in the response body — the invariant this table has wanted since the filter was written and could not state while there was no response to state it about. ### Repository-authored text in responses (descriptions, route summaries, the component diagram)

**Superseding the "AI-generated content" section (ADR-012, 2026-08-31).** That section listed five threats arising from sending repository content to an LLM prompt. **[ADR-013](DECISIONS.md#adr-013--repository-authored-descriptions-replace-the-llm-narration-layer) removed the LLM from the project**, so four of the five — prompt injection, secret files reaching a prompt, cost/latency inflation, and API-key exposure — are not mitigated but **eliminated**: there is no prompt, no provider, and no key. Do not reinstate this section without superseding ADR-013.

One threat survives the model's removal, because it was never about the model. Descriptions and route summaries are the **first repository *content* to enter a response body** — everything the API returned before was structure *about* the repository (paths, counts, line numbers), not text authored inside it. A comment is attacker-controlled, and it is now rendered in a browser.

**As of 2026-08-31 these rows have a call site** (ADR-020). `app/analysis/descriptions.py` extracts a file's leading header comment, `app/analysis/pipeline._analyze` calls it on every accepted file, and `app/analysis/graph_builder.py` copies the result onto `GraphNode.description`. Everything below that is described as happening "at extraction" now happens in that module, and the rows move accordingly.

**Later the same day, route summaries gained one too** (ADR-021). `app/analysis/routes.py` locates the comment above a detected handler and hands it to the *same* normalizer, passing `MAX_ENDPOINT_SUMMARY_CHARS` as the cap so it is applied while cleaning rather than as a second truncation. So `ServiceEndpoint.summary` is bounded and stripped by exactly the code path `GraphNode.description` is, and `MAX_SERVICE_ENDPOINTS` is now enforced in the pipeline loop rather than only at the model.

**On 2026-09-01 the component diagram gained one too** (ADR-024), and it is the third sink and the different one: `GraphNode.description` and `ServiceEndpoint.summary` are strings that sit *beside* a format, while `componentDiagram` puts directory names, route paths and route summaries *inside* Mermaid source. The control is therefore not primarily the sanitizer. **Node identifiers in the generated source are synthetic** — `c0`, `r0`, `ext` — so no repository string is ever concatenated into an identifier, an arrow, or a subgraph name, and repository text occupies exactly one position in the output: inside a double-quoted label. That removes the injection site rather than defending it, which is CLAUDE.md's stated preference; `component_diagram._label` is then the second line, dropping non-printables and removing the Mermaid/HTML metacharacters (double quote, `#`, `&`, `<`, `>`, `%`, backslash, backtick, `{`, `}`, `|`, `;`) before capping. A test asserts the structural half directly, by checking that no marker string appears anywhere outside a quoted label.

## Privacy

Intended user-facing statement, valid only once ADR-003 and ADR-007 are actually implemented:

> Repository contents are processed in memory for analysis and are not written to disk or stored.

ADR-003's half is now real for the whole ingestion and analysis path: `app/fetch/archive.py` streams the tarball through `gzip` and `tarfile` and yields member bytes, `app/analysis/pipeline.py` consumes them in memory and discards them with the request, and neither opens a file or imports `os`, `pathlib.Path`, `shutil`, or `tempfile` — pinned for the pipeline by `tests/test_pipeline.test_the_pipeline_has_no_path_to_the_filesystem`. **The graph builder is now covered too** — `app/analysis/graph_builder.py` handles only `PurePosixPath` values and builds a whole graph with `os.stat`/`lstat`/`listdir`/`scandir`/`open`/`access`/`readlink`/`mkdir` torn out from under it (`tests/test_graph_builder.test_no_filesystem_access`), the same argument the resolver already carries. **The routes were the last place that could have reintroduced a write, and they did not** (2026-09-01): `app/api/` opens no file, imports no `pathlib`/`shutil`/`tempfile`, and holds the graph only for as long as it takes to serialize it. That closes ADR-003's half of the statement across the whole request path. It is still not publishable as written, for the reason the sentence itself names — "processed in memory ... and not stored" is a claim about the *deployment* as much as the code, and nothing has verified that the target host does not log or spool a request body. Verify at deploy time (Day 3), not from this file. (ADR-013 removed the LLM layer, which was a third such risk, and with it the question of whether sending content to a third-party API is compatible with this statement at all.)

Do not publish this claim before verifying the implementation. Do not claim stronger guarantees than the code provides.

## Security Testing

Malicious archives are to be built in-process with `tarfile` + `io.BytesIO` rather than checked in as binary fixtures, so each attack is readable in the diff. **No security test may touch the network** — this is enforced, not trusted: `tests/conftest.py` replaces `getaddrinfo`, `create_connection`, and `socket.connect` for the whole session with a call that raises, so a test that forgets to stub fails loudly instead of quietly resolving a real name.

Done — `backend/tests/test_url_validation.py`, `backend/tests/test_net_guard.py`, `backend/tests/test_github_client.py` (477 cases):

- URL validation: homographs, userinfo, ports, private IPs, `evil.com/github.com/o/r`, encoded and literal traversal, NUL and other control characters, oversized input, and the `urlsplit` tab/CR/LF differential.
- Redirect handling: `302` to an attacker host, to a suffix of the allowlisted host, downgraded to `http`, protocol-relative, relative, and to the metadata endpoint; a second redirect; a missing `Location`. Each asserts the disallowed hop is **never requested**.
- Resolved-IP rejection, including the three addresses `is_global` alone would admit.
- The rejection body is asserted byte-identical across every rejected input, so no offending value can reach a response.
- **The codeload request carries no `Authorization`.** Both requests are driven through one client with a token configured, in the order the pipeline will make them; the download request is then sent and its headers asserted bare — under the header name *and* by searching every header value for the token. A second case supplies a client that was deliberately built with an `Authorization` default and asserts the download is still bare. Both were confirmed by mutation: removing the header strip fails the suite.
- `follow_redirects=False`, `trust_env=False`, and the absence of a client-level `Authorization` are each asserted directly, so a change to the client constructor cannot silently drop one.
- Preflight behaviour: the `403`/`404` collapse (byte-identical bodies), the size refusal (including at the exact limit and with the limit tightened through the environment), a malformed or hostile `/repos` body — wrong types, missing fields, a repository name of `../../etc/passwd`, a `default_branch` of `..` — and a hostile owner/repo/ref asserted to never reach the wire at all.
- The 12 controls in `app/fetch/github.py` were **mutation-tested**, one deletion at a time: all 12 are caught. The first pass had one survivor — removing the redirect-status check still failed on the missing `Location`, so a `200 OK` carrying a `Location` would have been treated as a download target. A test for exactly that was added.

Done — `backend/tests/test_archive.py` and `backend/tests/test_deadline.py` (142 cases), over archives built by `backend/tests/fixtures/tarballs.py`:

- Traversal in every spelling: `../../etc/passwd`, `..\..\x`, mixed `src\../../evil.ts`, `.` and empty components, and — the case that matters most — backslashes *below* the root directory, where the root-name pattern offers no cover.
- Symlinks, hardlinks, character and block devices, and FIFOs: each is skipped while a real file beside it is still yielded, so "skipped" is proven distinct from "aborted the archive".
- Absolute paths: POSIX, `C:\`, `c:/`, and UNC `\\server\share`.
- Malformed names: a NUL delivered through a pax `path` header, and lone surrogates from undecodable header bytes — plus two tests that assert the *fixtures* really produce a NUL and really write raw `\xff`, so the attack tests cannot pass by accident on a clean archive. A valid non-ASCII name is asserted to be **accepted**, because the rule is "decodable", not "ASCII".
- Roots: nine rejected root shapes, a second root, and a well-formed second root.
- **Unicode normalization is asserted *absent*.** A tar member name is bytes; neither `tarfile` nor this module normalizes it, and the tests pin that, because normalizing would *create* the attack rather than defend against one — under NFKC, U+FF0E folds to `.` and U+FF0F folds to `/`, so a name that is one inert component beforehand becomes `../etc/passwd` afterwards. Both lookalikes are asserted to survive as a single component, NFC and NFD spellings of the same grapheme are asserted to round-trip as distinct code points (a yielded path becomes a node ID and the subject of an `/api/source` token, so silently folding one into the other would make the token miss the file the user clicked), and real ASCII `..` is asserted still rejected beside them. Confirmed by mutation: inserting an NFKC normalization before the component check fails three of these tests.
- Bombs: a 1 GiB payload of zeros rejected after reading under half of a 1 MiB compressed archive, asserted to raise the *ratio* error rather than the extracted-size one, so the test would notice if it were the 256 MiB cap doing the work. Alongside it, two tests that the guard does **not** fire below the floor, since ordinary source compresses well past 100:1 in the first few kilobytes.
- Every cap: compressed download, extracted total, member count (including a real 50 000-member archive), member size, path depth, and path length — each with an at-the-limit case, and each in isolation with the other guards lifted so a test cannot pass on the wrong control.
- Streaming behaviour: abandoning the generator after one file is asserted to leave most of the archive unread, and the download cap is asserted to trip having pulled no more than the cap plus one chunk. Both use incompressible filler, because a megabyte of `b"x"` arrives in the decompressor's first read and makes such assertions vacuous.
- Malformed streams: empty input, non-gzip, gzip of garbage, truncated archive, truncated mid-member, and a header declaring more bytes than the archive contains. None escapes as a bare `TarError`, `EOFError`, or `zlib.error`.
- The rejection body is asserted byte-identical across different hostile paths, and asserted not to contain them.
- The 24 controls in `app/fetch/archive.py` were **mutation-tested**, one deletion at a time: 21 caught. The three survivors are documented in the code — the absolute-path check is subsumed by the empty-component and root-name checks, and a negative member size is unreachable because `tarfile` raises on the offset first. The first pass had a fourth survivor that was **not** redundant: deleting the `\` → `/` normalization left the suite green, because every backslash case then in the suite failed on the root-name pattern instead. Cases with backslashes below the root were added and the mutation is now caught.

Done — `backend/tests/test_secret_filter.py` and `backend/tests/test_path_safety.py` (142 cases):

- The secret filter is specified by two golden lists. The *allowed* list is the load-bearing one: every entry is a plausible source file that a sloppier rule eats — `src/secrets.ts` if the exact-name rule became a prefix, `monkey.ts` and `keyboard.tsx` if the `.key` suffix rule became a substring search, `server.ts` if `server.*` were read literally, `.gitignore` and `src/build.ts` if the directory rules matched by prefix or applied to the final component.
- Case variants of every family (`.ENV`, `ID_RSA`, `Private.PEM`, `NODE_MODULES/…`), because the machine that produced the repository is often case-insensitive and we are not.
- Fail-closed shapes — empty, `.`, `..`, traversing, absolute — asserted secret. None can reach the filter while `archive._check_member_name` runs first; the assertion is about what happens once that assumption breaks.
- A 20 000-path determinism sweep over boundary fragments (each rule's trigger, each rule's near-miss, separators, and characters where `casefold` is non-trivial: U+212A KELVIN SIGN, `ß`, `İ`). It asserts the filter is a pure function, returns a plain `bool`, and never raises — the analysis pass and `/api/source` judge the same path in two different requests, so a filter that could disagree with itself makes the second check worthless.
- Path safety is tested against **real symlinks** under `tmp_path`, not a stubbed `realpath`: a link to a sibling directory, one nested below the first path component, one to `/etc`, one dangling, and one pointing *inside* the base that must still be accepted. Plus the prefix-sibling case (`/…/base-evil` against `/…/base`) that `str.startswith` gets wrong, and a symlinked *base*, which an implementation that resolved only the candidate would refuse outright.
- Every rejection message is asserted to come from a fixed three-element set and to contain no fragment of the offending path.
- The 12 controls in `secret_filter.py` and the 6 in `path_safety.py` were **mutation-tested**, one deletion at a time: all 18 are caught. Both widening mutations are caught too — scoping the directory rules to every component instead of the parents, and swapping `commonpath` for `startswith`.

Done — `backend/tests/test_pipeline.py` (48 cases) and the SHA half of `backend/tests/test_archive.py` (11 cases). These test the **seam**, not the parts; every module involved was already covered in isolation:

- The join itself: all three requests made in order, the download actually sent, `./util` arriving unresolved at the caller. The credential-withholding assertion is repeated *here* rather than trusted from `test_github_client.py`, because ADR-009's guarantee is only worth anything at the call site that could undo it.
- **The secret filter's ordering, not just its outcome.** A spy on `extract_imports` records which paths were handed over, and `.env.ts` — a file a naive extension check would happily parse — is asserted never to appear. Deleting the filter fails four tests.
- Grammar selection: a `.ts` file whose first statement is `const x = <string>y;` yields its import under the TypeScript grammar and **nothing** under TSX, which is the whole reason the two are distinguished. Pointing `.ts` at TSX fails that test.
- The commit SHA: harvested from the root, taken from the same match that validated it, correct for a hyphenated repository name, and asserted to build a valid `Repository.commitSha`. A redirect that *does* pin a SHA is asserted not to override it. Re-deriving the SHA by splitting on the first hyphen instead of the captured group fails seven tests.
- `MAX_SOURCE_FILES`: truncation deterministic (front of archive order), flagged, counted over accepted files rather than members, and asserted to abandon the transfer — measured with a chunked response body, because httpx hands a whole `bytes` body over in one read and makes such an assertion vacuous otherwise.
- Failure containment: a hostile 200 000-child ERROR file and a binary file are each analyzed *between* two good files, and neither ends the run. A mid-transfer `httpx.ReadError` is asserted to surface as `UPSTREAM_UNAVAILABLE` rather than escaping untyped; a second redirect on the download is asserted never followed.
- No repository content in logs, and no filesystem path out of the pipeline — both described in their rows above.

Done — `backend/tests/test_api_routes.py` (23 cases). The first tests in this project that go through an HTTP request; the application is driven in process through `httpx.ASGITransport`, which opens no socket, with only the GitHub transport swapped by respx:

- **The error contract, applied.** Every rejection is asserted to carry exactly the three keys and the static message. A hostile URL (`https://evil.example/github.com/acme/widgets`) is refused **without the host appearing in the response**; a validation failure is asserted not to echo a marker string, the pydantic key `loc`, or the field name; an unforeseen `RuntimeError` carrying a filesystem path yields a 500 with no path, no `Traceback`, and no exception class name; and an unknown path and a wrong method are asserted to keep the contract shape rather than Starlette's `{"detail": …}`.
- **The request body cap**, both halves, each asserting the application never ran — a cap that fires after the body reached application code is not the control this table describes. The declared-length case additionally asserts **no chunk of the body was pulled at all**, which is the only thing distinguishing it from the byte counter. The at-the-limit case is accepted, so the cap is a boundary rather than an approximation.
- **The graph caps and the numbers that outlive them.** `MAX_NODES` and `MAX_EDGES` are each exercised with the other lifted, and every response is checked against a shared invariant: `stats.dependencies == len(edges)`, `sum(imports) == sum(importedBy) == dependencies`, `sum(externalImports) == stats.externalImports`, `root.fileCount == stats.files`, no edge naming a node that is not present, no node naming a parent that is not present, and a parent always preceding its children. A naive slice of `build_graph`'s output passes none of them. An uncapped control test runs first so the two cap tests cannot pass on an empty graph.
- **A `.env` in the repository reaches no part of the response**, and no repository content reaches a log record above `DEBUG` — both asserted over a real analysis rather than over a call.
- **19 controls across `app/api/` and the new cap logic were mutation-tested**, one at a time: all 19 caught. One apparent survivor was a **no-op mutation** (`_nodes` is only ever handed the surviving files, so there is no line to delete — rewritten as passing the full mapping, it fails four tests). One was a **real gap**: deleting the declared-`Content-Length` check left the suite green, and the test asserting the body is not read was added because of it.

The happy path has additionally been run against real GitHub repositories on 2026-08-31 via `backend/scripts/smoke.py` — deliberately *not* a pytest test (ADR-014), because `tests/conftest.py`'s session-wide socket block is a guarantee and a marker that lifted it would be an escape hatch available to every future test. Three repositories analyzed cleanly and two error branches (`RepositoryNotFoundError`, `NoSupportedFilesError`) were confirmed against real responses. This proves the transport, the redirect shape, the chunking, and the archive-root parsing work on real data; it proves nothing about the adversarial rows, because a real repository does not attack you.
